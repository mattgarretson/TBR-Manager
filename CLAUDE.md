# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm run dev          # Vite dev server on :3000
npm run check        # typecheck + lint + unit tests + production build — run before each commit
npm run typecheck    # tsc --noEmit
npm run lint         # eslint (typescript-eslint + react-hooks)
npm run test:unit    # vitest run
npm run build        # vite build -> dist/
npm run preview      # serve dist/ locally (service worker only registers in production builds)
```

Single test file / single case:

```bash
npx vitest run tests/library-service.test.ts
npx vitest run tests/app-behavior.test.tsx -t "opens a shared book"
```

Node >= 22.13 is required. Vitest runs jsdom, single-worker and `fileParallelism: false` on purpose — `tests/setup.ts` installs `fake-indexeddb/auto` plus global `matchMedia`/`navigator.storage`/`navigator.serviceWorker` stubs, and parallel files would share that state.

## Stack

Plain React 19 single-page app built with Vite (`index.html` → `src/main.tsx` → `PlotPileApp` in `app/plot-pile-app.tsx`). Deployed as static files to GitHub Pages by `.github/workflows/deploy.yml` on push to `main`. `vite.config.ts` sets `base: "./"` so the build works under the `/TBR-Manager/` project path. Fonts come from `@fontsource-variable/*` packages (bundled, offline-safe).

History: the app was originally generated by ChatGPT Codex on OpenAI's "Sites" platform (Next 16 via vinext, Cloudflare Worker, D1/R2 legacy migration routes). That scaffold and the legacy migration were removed when moving to GitHub Pages in September 2026; see git history before `move-to-github-pages` if you need it.

## Architecture

Plot Pile is a single-user, device-local PWA. **IndexedDB is the authoritative store** — there is no server. Layers, strictly inward-depending:

1. `lib/library/model.ts` + `selectors.ts` — pure domain rules (tag/series-name normalization, sorting, filtering, date math, backup build/parse). No React, no storage, no network.
2. `lib/library/repository.ts` — the `LibraryRepository` interface. `indexeddb-repository.ts` is the production implementation; `tests/helpers/memory-repository.ts` is the test double. Every multi-record mutation is one IndexedDB transaction.
3. `lib/library/service.ts` — `LibraryService` owns ID generation, timestamps, validation, and compound commands. `now`/`createId` are injectable, which is how tests stay deterministic.
4. `app/use-library-controller.ts` — the *only* React boundary that touches persisted library state. Loads the library on mount, exposes command functions, converts thrown errors into user-facing strings via `lib/library/errors.ts`.
5. `app/plot-pile-app.tsx` (`PlotPileApp`) + `components/library/*` — view state, filters, editor drafts. Components never import IndexedDB helpers; they call controller commands passed as props.

`lib/covers/open-library.ts` is a network-only client injected into components as `coverClient`; it never touches IndexedDB. Open Library cover search/download is the app's only runtime network call. `lib/share/parse.ts` is a pure parser for shared titles/URLs.

Non-library device state lives in localStorage, not IndexedDB: theme (`app/use-device-settings.ts`) and library/series view preferences (`components/library/view-preferences.ts`). Backup timestamps live in the IndexedDB `meta` store.

### Compatibility contracts

Treat these as frozen unless you are deliberately versioning them:

- IndexedDB name `plot-pile-library`, version 1, stores `books` / `series` / `meta`. Never rename or bump the version without an upgrade fixture covering an existing database.
- Backup format `{ app: "Plot Pile", version: 1, ... }` must stay readable and writable (`tests/fixtures/backup-v1.json`). Backups are how users move between devices and hosting addresses, including restoring libraries exported from the old chatgpt.site deployment.
- The production URL is effectively a contract too: IndexedDB is origin-bound, so changing hosts strands every user's data unless they do a backup/restore.

`docs/architecture.md` holds the full invariant list and change rules (add a domain test before changing normalization/sorting/filtering/date/backup behavior; add a repository test before changing a transaction or schema version).

### PWA

`public/sw.js` caches the app shell (network-first for navigations, cache-first for same-scope assets, everything outside its scope — e.g. Open Library — bypassed). It resolves all paths against its own URL. Its `BUILD_ID`/`BUILD_FILES` placeholder lines are rewritten in `dist/sw.js` by the `serviceWorkerPrecache` plugin in `vite.config.ts`: install precaches every emitted file into a per-build cache, and activate deletes older `plot-pile-shell-*` caches. Keep those two lines verbatim — the build fails if the plugin can't find them. It is registered from `use-device-settings.ts` only when `import.meta.env.PROD`; in dev it unregisters any existing worker so cached modules don't go stale. `public/manifest.webmanifest` uses relative `id`/`start_url`/`scope` and declares a GET share target; shared `title`/`text`/`url` params are consumed by `sharedLaunchFromLocation` in `app/plot-pile-app.tsx`, which routes single links to the book editor and multi-link shares to `LinkImport`, then strips the params from the URL. `tests/pwa-contract.test.ts` asserts the manifest and service-worker behavior directly — update it alongside either file.

## Testing conventions

`tests/app-behavior.test.tsx` drives the real `PlotPileApp` through Testing Library with `controllerDependencies={{ repository, service }}` — a `MemoryLibraryRepository` and a `LibraryService` with fixed `now`/`createId`. Prefer extending that file for UI behavior rather than mounting individual components. Domain, selector, service, repository, share-parsing, and cover-client tests are separate files and use no DOM.

## Styling

`app/globals.css` is a single hand-written stylesheet with semantic class names (`app-shell`, `card-grid`, `primary-button`) and six themes (four light, two dark: `graphite`, `nightshade`) selected via `html[data-theme="..."]`. Colors go through the custom properties on `:root`; don't hardcode hex values in rules, or they break in the dark themes — dark themes use light accents, so text on `--berry`/`--ink` fills uses `--on-berry`/`--on-ink`. Tailwind is imported (via PostCSS) for its base layer only — do not introduce utility-class styling. `settings-view.module.css` is the one CSS module.
